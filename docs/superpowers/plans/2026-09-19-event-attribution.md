## Constraints and shared interfaces

- This directory is not a Git repository. Work in place; do not create a repository, worktree or commits. Preserve existing files and model/config changes outside owned scope.
- Root owns `app.py`, new `assumption_registry.json`, API integration tests, docs. Backend implementer owns `attribution.py`, `test_attribution.py`. Frontend implementer owns only `index.html`.
- No model-asserted automatic numerical breach. No automatic thesis edits. Do not read or send evaluator answer files. Missing evidence/unaddressed assumptions never become supported.
- Registry root: `{version:"1.0", assumptions:[{id,title,claim,baseline_status:"working"|"approved_synthetic",criticality,covenant_ids:[str],source}], relationships:[{source,target,type}]}`. Root creates it. `attribution.load_context()` returns registry fields plus `covenants` from the library (`covenant_id`, `title`, `selection_and_type`, `clause_text`, `interpretation_record`, `agreement_version`) and `profiles` from `profile_clauses`; shared contract context stays server-side for the model.
- `attribution.prepare_event(body, packet=None)` validates text/packet and dates, returns `{id,title,event_date,available_at,review_date,sources:[{document_id,locator,text}]}`. For typed text use source ID `event-input`, locator `Event description`; system availability defaults to today. Packet sources use packet ID and actual locators; availability comes from the packet. Review defaults to availability when not supplied. Reject review before source availability, empty/nonstring text, invalid dates, unknown/conflicting profiles. Permit unknown event_date as empty; future occurrence may describe a proposal and must be interpreted as such. Text bound 48000 characters.
- `attribution.selected_covenants(profiles)` accepts a list of allowed profile keys. CORE is always included; LIQUIDITY selects PC24+PC25, INTEREST/CASH-COVERAGE cannot coexist, REVOLVER replaces PC01 with PC30. Reject unknown profile values. GOVERNANCE selects PC22+PC23 for this demo.
- `attribution.analyze_event(event, profiles, *, api_key, model, completion=None)` returns `{id,event,profiles,engine,model,attributions,coverage,candidates,warnings,error,decisions:{}}`. `completion` is an optional external-model-boundary callable receiving system/user messages and returning parsed response dict for offline validation tests; production uses NVIDIA chat completions. `engine` is `nemotron` or `unavailable`; exceptions yield explicit unavailable output with every assumption unassessed, not fallback fiction. The API may still store that event for retry.
- Model response: `{attributions:[{target_type:"assumption"|"covenant",target_id,relation_type,risk_direction,proposed_status,rationale,evidence:[{document_id,locator,quote}],counterevidence:[],missing_information:[],suggested_action,proposed_adjustment,path:[]}],candidates:[{claim,rationale,evidence:[]} ]}`.
- `relation_type`: `direct_assumption_evidence`, `downstream_exposure`, `covenant_input`, `covenant_trigger`, `covenant_permission`, `evidence_gap`. `risk_direction`: `adverse`, `beneficial`, `neutral`, `mixed`, `unclear`. Assumption `proposed_status`: `supported`, `weakened`, `contradicted`, `insufficient_evidence`, or null. Downstream exposure must have null status. Suggested actions: `monitor`, `request_information`, `review_assumption`, `recalculate_covenant`, `review_permission`, `propose_revision`.
- Validated attributions gain host-generated `id`, `target_title`, `baseline_status` for assumptions, `applicability` (`selected` or `inactive` for clauses; selection is not proof of a triggered/due test), `verified:true`, `target_version`. All evidence must verify at its exact document+locator after whitespace normalization; counterevidence too. At least one verified event citation per attribution. Unknown IDs or malformed findings are excluded with visible warnings. No all-document fallback for a wrong locator. Inactive covenants may be shown for context, marked inactive; actions must not imply current obligation. Downstream `path` must end at target and use existing directed edges, rooted in a valid direct assumption attribution. Unaddressed assumptions in `coverage` remain `unaddressed`; withheld results remain visible through warnings. Scope/meaning uncertainty must be explicit.
- API `GET /api/attribution-context` returns context. `POST /api/attribute`: `{text?,packet_id?,title?,event_date?,available_at?,review_date?,profiles:["CORE"],engine?}` returns record. `POST /api/attribution-decision`: `{event_id,attribution_id,decision:"accept"|"dismiss",reason}` records a review decision only. `GET /api/history` additionally returns `events`. No deletion or automatic source/profile mutation.
